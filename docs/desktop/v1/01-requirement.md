## 1. 现象

1. 上游 `AutoTranscriber`（github.com/GuyueHermit/AutoTranscriber，HEAD c7b7981）已具备扒谱内核能力，但**仅有 CLI 入口**：需手敲 `python main.py -i 歌曲.mp3 -o out.mid --separate --track vocals --n_peaks 2` 之类命令，普通用户无法使用。
2. 参数需记 10+ 个命令行开关（`--n_peaks` / `--hop_length` / `--onset_threshold` / `--min_note_duration` / `--simplify` / `--piano` / `--perceptual` / `--demucs_model` …），模式间参数耦合（如人声须 `n_peaks=2`，和弦须 5-8），无任何引导。
3. 长任务（Demucs 分离 1-5 分钟 + CQT 分析）无进度反馈，CLI 只有 stdout 文本行，用户无法判断是否卡死。
4. 「导入已分离好的音频直接扒谱」这一诉求，CLI 无对应入口（`--separate` 强制走 Demucs，无法跳过分离直接指定 vocals/instrumental 文件）。
5. 上游 README 明显落后于源码（源码已含 NNLS 谐波模板拟合、CREPE 深度学习人声检测、感知模式 perceptual，README 均未记载），按 README 判断能力会误判。
6. 上游仅导出 MIDI 与 PDF，无 MusicXML；轨名、program 等 MuseScore 侧呈现细节未受控。

## 2. 目标

1. **G1 零命令操作**：用户拖入音频 + 选模式 + 点按钮，三步内得到 MIDI，全程不接触命令行。
2. **G2 双功能页覆盖 6 条路径**：功能页 1「歌曲扒谱」覆盖 ①全自动双轨 ②只扒伴奏 ③只扒人声旋律 ④基本扒谱（乐器/单音轨，下拉选择）；功能页 2「基本扒谱」覆盖 ⑤单音轨 / ⑥多音轨。
3. **G3 已分离音频直入**：支持用户导入外部已分离的 vocals + instrumental 文件对，跳过 Demucs 直接扒谱。
4. **G4 主流格式通吃**：mp3 / wav / flac / m4a / aac / ogg / opus / wma / aiff 输入不失败，失败须给明确中文原因而非堆栈。
5. **G5 过程可见**：分离 / 频谱分析 / 音符追踪 / 生成 MIDI 四阶段进度 + 百分比 + 实时日志，长任务不 seeming 卡死。
6. **G6 MuseScore 可用**：导出的 .mid 用 MuseScore 4 打开，轨名正确（人声/伴奏/乐器名）、program 合理、tempo 正确、可直接编辑。
7. **G7 四方向可切换视觉**：霜蓝玻璃 / 暗房琥珀 / 深海声谱 / 素纸墨青 四套完整视觉，运行时热切换，供主上挑选与长期使用。
8. **G8 桌面级质感**：无边框窗口 + 圆角 + 弥散阴影 + chrome 与内容区无可见交界线；动效遵守 Taste 工程原则（禁 ease-in、时长 <300ms、press scale 0.97、origin-aware）。
9. **G9 慎之勇者工程态度**：每个功能点须经多轮对抗式自测（边界/异常/并发/取消/长时间任务），反复验证到无法复现缺陷才可交付，不接受「看起来能跑」。

## 3. 方案与取舍

### 3.1 总体架构（三层）

```
┌─ src/                 Tauri 2 + React 18 + TypeScript + Tailwind（前端）
│  ├─ 两个功能页 + 四方向主题层（CSS 变量驱动热切换）
│  └─ Tauri command / event 通道
├─ src-tauri/           Rust 壳：无边框窗口、文件对话框、目录揭示、sidecar 生命周期管理
└─ engine/              Python 引擎（venv + vendored 上游）
   ├─ bridge.py         适配层：参数映射 / 阶段进度上报 / 轨道编排 / 错误中文化
   ├─ pipeline.py       六条产品路径的编排实现
   └─ third_party/AutoTranscriber/   上游只读快照
```

**取舍**：不选 PySide6 单体——视觉天花板受限（工程风），与 G7/G8 冲突；不选 Electron——体积 150MB 内存高，与「双击即用、可掌控」体验冲突，且主上已有 Tauri 经验。Tauri 2 体积约 15MB，无边框圆角有现成技能与先例。

### 3.2 上游零改动（红线 B-1）

上游 vendor 至 `third_party/AutoTranscriber`，**一字不改**。所有适配在 `engine/bridge.py` 完成。

**取舍与代价**：上游无进度回调机制，故进度上报采用「stdout 逐行解析 + 阶段推断」方案（`bridge.py` 捕获上游 `print` 输出，映射为四阶段进度）。相比 fork 上游加回调，代价是进度百分比为估算值而非精确值，但守住只读红线、避免上游升级冲突。**待侦察报告确认**若某能力必须改上游才能实现，则登记例外台账并请主上拍板。

### 3.3 六条路径的编排（`engine/pipeline.py`）

| # | 路径 | 分离 | 扒谱算法 | 输出轨 |
|---|---|---|---|---|
| 1 | 全自动双轨 | Demucs htdemucs | 伴奏走 CQT 多音高；人声走 CREPE（可用时）否则 pYIN | 2 轨：人声 / 伴奏 |
| 2 | 只扒伴奏 | Demucs htdemucs | CQT 多音高（n_peaks 5-8） | 1 轨：伴奏 |
| 3 | 只扒人声旋律 | Demucs htdemucs | CREPE / pYIN（n_peaks 1-2） | 1 轨：人声 |
| 4 | 基本扒谱（乐器/单音轨） | 无 | CQT 多音高 或 感知模式 | 1 轨 |
| 5 | 基本扒谱（单/多轨） | 无 | 同上，轨数由参数定 | 1 或 N 轨 |
| 6 | 已分离音频直入 | 跳过，用户提供文件对 | 同 1，各轨分别扒 | 2 轨 |

**取舍**：路径 1 的人声轨优先用 CREPE（深度学习，音高更准），但 CREPE 依赖 TensorFlow、体积大、首次加载慢。故设为「可用则用、不可用降级 pYIN」，并在 UI 明确提示当前用的是哪条，避免用户误判精度。

### 3.4 导出策略（红线 B-3）

**仅导出 MIDI**。轨名映射：人声轨 → `Voice`（program 53 Voice Oohs 或 52 Choir Aahs）、伴奏轨 → `Piano`（program 0）；可多轨时按 `Track 1/2/…` 或用户自定义名。tempo 由参数面板 BPM 写入。

**取舍**：不做 MusicXML 导出（主上裁决）。不做 PDF（主上未要求，MuseScore 自行导出即可）。**代价**：MuseScore 打开 .mid 落在钢琴卷帘/导入总谱视图，不如 .musicxml 的分谱表体验精细——此项为主上已知的取舍。

### 3.5 四方向视觉（红线 B-2 / B-4）

| 方向 | 定位 | 主色 | 强调色 | 布局隐喻 |
|---|---|---|---|---|
| 霜蓝玻璃 Frost | 浅色冷调，通透静谧 | 雾白 / 极浅灰蓝 | 珊瑚橙 | 大留白居中，玻璃层浮于雾面 |
| 暗房琥珀 Cellar | 深炭暖调，录音棚控制台 | #1A1815 深炭（非纯黑） | 琥珀金 | 面板分区用刻度线，等宽数字，旋钮隐喻 |
| 深海声谱 Abyss | 深靛蓝，频谱可视化主角 | #14182B 深靛 | 青绿 / 电光蓝 | 波形/频谱全宽铺底，界面退为半透明浮层 |
| 素纸墨青 Paper | 纸白极简编辑风 | 纸白 | 墨青 + 朱砂点 | 网格 + 线条 + 字重建立秩序，近乎无阴影 |

**取舍**：四套均以 CSS 变量为单一主题源，切换只换变量不重挂组件树（保 200-300ms 平滑过渡与状态不丢）。**明确排除**：品红/霓虹粉紫、纯黑大面积背景、装饰性散景球体、玻璃卡片套玻璃卡片、emoji 图标、满屏浮动卡片。

### 3.6 依赖与环境

- 引擎 venv：`engine/.venv`（Python 3.13），torch cu124 + torchaudio + librosa + demucs + av + pretty_midi
- 硬件：RTX 3080 10GB，Demucs 走 CUDA
- 打包：Tauri NSIS installer；Python 引擎随包分发（venv 目录整体打包 or 首启引导安装，二者待定——见 plan P4）
- MuseScore 4 已装于 `C:/Program Files/MuseScore 4/bin/MuseScore4.exe`，仅用于**验收自测**（打开产出 .mid 验证），不做应用内依赖

## 4. 不做什么

1. **不改上游任何文件**（B-1），不 fork、不打 patch 到 `third_party/`。
2. **不实现 MusicXML / .mxl 导出**（B-3）。
3. **不做音频编辑**（裁剪、混音、变速、EQ）——本应用只做「音频进、MIDI 出」。
4. **不做账号/登录/联网服务**——纯本地工具，主上数据不出机器。
5. **不做音频上传云端处理**——Demucs 与扒谱全在本地跑。
6. **不做多轨 MIDI 的鼓组分轨**（不分离 drums/bass/other 为独立轨），双轨即人声 + 伴奏。
7. **不做移动端 / macOS / Linux 适配**——本期只出 Windows x64。
8. **不做实时预览播放 / 钢琴卷帘编辑器**——只导出文件，编辑交给 MuseScore。
9. **不用品红 + 黑色配色**（B-2），不预选单一视觉方向替主上决定（B-4）。
10. **不引入付费 API / 需密钥的第三方服务**（红线：预算安全）。

## 5. 验收口径

### 5.1 功能验收（逐条可复跑）

| 编号 | 验收项 | 判定方法 |
|---|---|---|
| A1 | 六条路径全部产出非空 .mid | 用 `test_audio/chord_progression.wav` 与一段真实 mp3，对 6 条路径各跑一次，`pretty_midi` 读回 note 数 > 0 |
| A2 | 主流格式通吃 | ffmpeg 转出 mp3/m4a/aac/ogg/opus/wma/aiff 各一份，逐个拖入应用，全部成功；失败须给中文原因 |
| A3 | 已分离音频直入 | 手工分离一对 vocals/instrumental，导入后跳过 Demucs 直接出双轨 |
| A4 | 四阶段进度可见 | 跑一条 3 分钟歌曲，UI 依次显示「分离人声/分析频谱/追踪音符/生成 MIDI」+ 百分比 + 实时日志 |
| A5 | MuseScore 可用 | 产出 .mid 用 MuseScore 4 打开：轨名正确、program 合理、tempo 正确、音符可编辑 |
| A6 | 拖放全流程零命令行 | 从打开应用到拿到 .mid，全程不敲任何命令、不开终端窗口 |
| A7 | 四方向热切换 | 4 版视觉均可完整操作（拖放/下拉/进度/结果态），切换不丢状态、过渡 200-300ms |
| A8 | 无边框窗口 | 窗口无系统标题栏、右上三键、圆角 + 弥散阴影、chrome 与内容无可见交界线 |

### 5.2 工程质量验收（G9 慎之勇者态度）

| 编号 | 验收项 | 判定方法 |
|---|---|---|
